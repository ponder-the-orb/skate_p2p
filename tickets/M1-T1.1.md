FILES: skate_signaling_server/server.js,

SPEC: PROTOCOL.md §2–§5 + Appendix A transitional rule; ARCHITECTURE.md §6
NOTES (Architect rulings):
  - Transitional framing, M1 only: first byte 0x01 → v1 control frame,
    validate per §3, handle JOIN. Only JOIN is valid from clients; other
    inbound control → drop + log. Any other first byte → opaque legacy
    game frame: forward verbatim to the one other socket in the sender's
    room. Never parse, never echo, never cross rooms. Sender not in a
    room → ERROR 0x04.
  - Server must never crash on any input: length-check before every
    read; malformed → drop + log (§3).
  - playerId: non-zero uint16 from a global counter. roomCode: random
    10000–99999, re-roll on collision with an active room. All
    multi-byte fields big-endian (readUInt16BE/writeUInt32BE, never LE).
  - Disconnect: send PEER_LEFT to the remaining peer; delete the room
    when it has zero sockets. A one-socket room accepts a second JOIN
    as a normal join.
  - JOIN from a socket already in a room: remove it from its old room
    first (as if disconnected — PEER_LEFT to that peer, delete if
    empty), then process the new JOIN.
ACCEPTANCE:
  - JOIN (0x01): code 0 creates (server picks the code), nonzero joins.
    JOINED (0x02) returns playerId + roomCode + role per §5 layout
    (role 1 = creator/sets first, 2 = joiner).
  - PEER_JOINED (0x03) to the creator when the second socket joins.
  - ERROR (0x0F): 0x01 room full, 0x02 room not found, 0x03 malformed,
    0x04 not in a room.
  - Game frames only ever reach the one other socket in the same room;
    two rooms running at once show zero leakage.
  - rooms_smoke.js proves: full-room rejection, bad-code rejection, no
    cross-room leakage, empty/garbage frames don't kill the process.
