TICKET M1-T1.2 — Client lobby, identity & v1 control parsing
GOAL: App boots to a lobby that creates/joins rooms via v1 JOIN; client
parses server control frames (JOINED, PEER_JOINED, PEER_LEFT, ERROR);
gameplay stays on legacy 0x02/0x03 until M2.
FILES:
  - new lib/core/network/packet_codec.dart  (v1 encode/decode, control only)
  - new lib/ui/screens/lobby_screen.dart
  - lib/core/network/packet_dispatcher.dart (first-byte branch: v1 vs legacy)
  - lib/core/state/app_state.dart           (phase enum + identity fields)
  - lib/main.dart                           (root switches screens on phase)
  - lib/ui/screens/match_screen.dart        (real playerId; role label)
  - test/ (extend dispatcher tests; new packet_codec_test.dart)
SPEC: PROTOCOL.md §2–§5 + §7 examples + Appendix A transitional rule
(client paragraph); ARCHITECTURE.md §5 phases.
NOTES (Architect rulings):
  - Dispatcher branches on byte 0. 0x01 → v1 control frame: validate
    per §3 (length ≥ 5, version, length == 5+payloadLen, known opcode
    with exact payload size), then handle 0x02 JOINED / 0x03
    PEER_JOINED / 0x04 PEER_LEFT / 0x0F ERROR; anything else → drop +
    log, never throw. Any other first byte → existing legacy path,
    unchanged. Remember: v1 opcode is at byte 1, legacy opcode at byte 0.
  - packet_codec.dart is the start of M2's PacketCodec. Do not touch
    BinaryPacker; it dies at M2.
  - JOIN goes out with senderId 0x0000 (no id yet). After JOINED, all
    legacy sends use the assigned playerId — the hardcoded 1024 dies.
  - AppState: ClientPhase { disconnected, lobbyIdle, waitingForPeer,
    inMatch } plus playerId, roomCode, role. Root widget renders
    LobbyScreen or MatchScreen from phase. No Navigator push/pop for
    network-driven transitions — async pops are a bug farm.
  - Flow: Create → JOIN(0). Creator: JOINED → waitingForPeer, lobby
    shows the code big + "waiting for peer…" + Cancel; PEER_JOINED →
    inMatch. Joiner: JOINED → inMatch directly.
  - Errors: inline status text in the lobby (0x01 "Room full", 0x02
    "Room not found", else "Error 0xNN"). No SnackBars.
  - PEER_LEFT, Cancel, or leaving a match: disconnect the socket,
    reconnect fresh, land on lobbyIdle with a short notice. This avoids
    stale half-empty rooms and role ambiguity; real reconnect-grace is
    M3.
  - Socket still connects at boot; Create/Join disabled until
    connected. Join field: digits only, 5 digits, numeric keyboard.
  - No new dependencies.
ACCEPTANCE:
  - Boot → lobby. Create on device A shows a real server code; typing
    it on B lands both in MatchScreen; legacy score button still works
    between them, logs show the real playerId as sender.
  - Wrong code → "Room not found" inline; third device on a live code
    → "Room full" inline.
  - Killing app B returns A to the lobby with a notice.
  - Tests: §7 worked examples as byte-for-byte fixtures (codec emits
    the exact JOIN-create bytes; the JOINED fixture parses to playerId
    7, room 41235, role 1); PEER_JOINED / PEER_LEFT / ERROR parse;
    truncated and garbage v1 frames drop without throwing; legacy 0x02
    dispatch still passes (regression).
  - flutter analyze clean · flutter test passes · CHANGELOG updated.
OUT OF SCOPE: GameEngine, v1 game opcodes, any wire-format change (M2).
Reconnect-grace (M3). Server changes — if the server disagrees with
the spec, FLAG it; the spec wins.
IF IT BALLOONS: land codec + dispatcher + AppState + tests first,
report DONE-PARTIAL, and we split the UI into T1.2b.
