       (empty stays legal; render as "Unnamed trick")

    3. setting + peer is setter → waiting state, peer clearly "up"
    4. defending + I'm defender → trick name huge + LANDED / BAILED
    5. defending + peer defends → waiting state
    6. gameOver → full-screen overlay: WIN or LOSE, big; final letters;
       REMATCH button; after my vote → "waiting for opponent"; if the
       peer voted first → say so ("Opponent wants a rematch")
    7. abandoned → existing lobby-return already handles it; no work
  - Letters render as accumulating S·K·A·T·E per player; a newly gained
    letter should be noticeable (simple emphasis — no animation deps).
  - Dark theme stays; bold and readable on a phone. Taste is yours
    within that.
  - Format debt: run `dart format .` and commit any pure-format fallout
    as a separate `style:` commit so the UI diff stays readable. DoD
    includes `dart format --output=none --set-exit-if-changed .` passing
    repo-wide.
  - Widget tests: drive a real AppState through its public handlers and
    intents to reach each state (no send callback needed — it no-ops),
    pump MatchScreen, assert the right controls/text. No mocks, no
    test-only setters.
