NOTES (Architect rulings):
  - relayUrl stays a top-level const in main.dart, same name, same
    default:
      const String relayUrl = String.fromEnvironment('RELAY_URL',
          defaultValue: 'ws://127.0.0.1:8080');
    TRAP: Dart guarantees fromEnvironment only inside a const
    context; anywhere else it may throw or quietly return the
    default. Keep the const. Doc-comment the flag with one
    --dart-define example on the declaration.
  - No validation, no friendly copy, no lobby display. A bad URL
    already lands in SignalingService's "Connection Failed" path;
    nicer copy is T4.4.
  - The default stays localhost. Whether release builds flip it to
    the public relay is T4.3's ruling, not this ticket's.
  - test/relay_url_test.dart pins the default: relayUrl ==
    'ws://127.0.0.1:8080' when no define is passed — exactly what CI
    (T4.1) will run. The override is compile-time and cannot be unit
    tested; the Producer's manual pass proves it.
  - DEV_SETUP "Run the client": replace the "Until M4-T4.0 makes it
    a build-time flag…" paragraph with the flag as it now exists —
    the default; that the value is baked at compile time, so it goes

    change it); one LAN example
    (`--dart-define=RELAY_URL=ws://<laptop-ip>:8080`) and one wss

    or edit `relayUrl` for the session)" becomes "via
