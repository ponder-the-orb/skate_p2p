NOTES (Architect rulings):
  - rejoin_store.dart is a LEAF beside clip_store: pure Dart SDK
    only. Ruling: dart:convert is in-bounds for leaves — the
    register's "core/io only" wording meant "no Flutter, no
    packages"; I clarify the register at the next docs pass.
    API: save(roomCode, playerId), touch() (rewrites savedAt only),
    load() → record or null, clear(). File rejoin.json in the
    injected directory. Corrupt or missing JSON → null, never
    throw (§3 validation culture applies to disk too).
  - path_provider stays imported ONLY in clip_environment.dart
    (ADR-008 rider). Add resolveRejoinStore() there, mirroring
    resolveClipStore(). main.dart:
    resolveRejoinStore().then(appState.attachRejoinStore) —
    fire-and-forget, no await before runApp.
  - AppState: attachRejoinStore(store); every use null-safe — no
    store attached means the feature is silently off, which is what
    every existing test gets. Hooks: handleJoined → save; each
    applied game opcode handler → touch (freshness = last
    activity, not join time — a 40-minute game must still read
    fresh); the 0x02 room-not-found branch → clear ONLY if the
    attempt was the rejoin flow (one nullable _pendingRejoinCode
    field, set by the lobby tap, nulled on any JOINED or ERROR).
    A manually mistyped code must never delete a live save.
  - TRAP: these hooks fire inside notifier paths. Writes are
    fire-and-forget (unawaited) — never block dispatch on disk.
    load() happens once, in the lobby's initState.
  - Lobby shows "Rejoin last game" only when load() returns a save
    with now − savedAt ≤ 180 s (grace is 120; 60 covers relaunch).
    Display heuristic ONLY — tapping when the room is gone just
    takes the existing room-not-found path, which already shows
    friendly copy and now also clears the save. Advisory, like the
    timer: the client never concludes the room is dead (ADR-003's
    cousin).
  - Tap sends a plain JOIN with the saved code. NOTHING else — the
    server re-seats the original playerId itself (PROTOCOL §5).
    playerId is saved because ROADMAP names it and it's free;
    it is not needed on the wire.
  - Tests: rejoin_store fully unit-tested with temp dirs (save,
    touch moves savedAt, load, clear, corrupt json → null).
    app_state: JOINED saves; opcode touches; 0x02-after-rejoin
    clears; 0x02-after-manual-join does NOT clear. Lobby widget
    tests via an injected temp-dir store: fresh save → button,
    stale/absent → no button. No mocks of path_provider — the
    resolve function is manual-pass territory.
