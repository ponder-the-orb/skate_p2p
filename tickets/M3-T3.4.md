it out through the system share sheet with a challenge line. Local
only. Zero game-state effects. This is the growth loop.

NOTES (Architect rulings):
  - lib/media/ is a new LEAF layer: dart:io + dart:core only, no
    Flutter imports — unit-testable like the engine. clip_store owns
    the clips dir (app documents/clips/), filenames
    clip_<millisSinceEpoch>.mp4, list-newest-first, delete, and the
    share-text builder: trick name or "this" →
    'Land it or take the letter 🛹 "<trick>" — skate_p2p'.
    No room codes in share text — codes die with rooms; dead links
    are jank.
  - PLATFORM TRAP, read twice: the camera plugin does NOT support
    Linux desktop, and test VMs have no cameras. Probe
    availableCameras() lazily, once, behind an injectable seam; no
    camera → the Record entry simply doesn't render, and nothing
    crashes. The Producer's PC build must run exactly as today.
  - Recording is MANUAL start only — never auto-record (privacy).
    Rear camera, enableAudio true, ResolutionPreset.medium
    (deliberate: share-sheet-friendly file sizes beat vanity pixels;
    messengers recompress anyway), 30 s hard cap with auto-stop and a
    visible remaining-seconds indicator.
  - Camera lifecycle is where these features crash: controller owned
    by RecordScreen's State, disposed in dispose(), a
    WidgetsBindingObserver disposes on inactive and reinitializes on
    resumed, every plugin call try/caught into a friendly "Camera
    unavailable" state. Never throw to the user.
  - Record/replay are USER-driven, synchronous flows → Navigator
    routes are correct here. The phase-driven root stays authoritative
    for all network-driven transitions (T1.2 ruling unchanged) — if a
    network transition fires mid-recording, the match root wins when
    the user backs out; do not fight it.
  - Recording has ZERO game-state effects: it never reports results,
    never touches AppState.game, and stays available during
    peerDisconnected (it's local; grace is irrelevant to it).
  - Replay screen: video_player looping preview, Share / Delete /
    Back. Back keeps the file; kept clips live in the "My clips" list
    (filename date, tap → replay screen, same Share/Delete).
  - Tests: clip_store fully unit-tested with temp dirs (naming,
    ordering, delete, share text incl. empty trick name). Widget
    tests: Record entry present in states 2 & 4 and absent in
    1/3/5/6 via the injectable camera-availability seam set true;
    entire suite green with it false (VM reality). Do NOT attempt to
    mock the camera or video_player platform internals — hardware
    behavior belongs to the Producer's manual pass.
